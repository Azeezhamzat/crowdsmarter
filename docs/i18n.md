# Localization: scope and status

## What exists today

- **Frontend**: a minimal, dependency-free i18n layer (`frontend/src/lib/i18n.ts`) —
  a typed per-page message catalog (`defineCatalog`), a locale store shared across the
  app via `localStorage` and `useSyncExternalStore` (`useLocale`/`setLocale`), and a
  `<LanguageSwitcher>` component. Three locales are wired end-to-end: English (default),
  French, and Portuguese.
- **Backend**: Django's standard i18n machinery is active (`LocaleMiddleware`,
  `LANGUAGES`, `LOCALE_PATHS`), with `.po`/`.mo` translation files under
  `backend/locale/{fr,pt}/LC_MESSAGES/`.

## Coverage — deliberately scoped, not exhaustive

Per the "infrastructure-first, highest-traffic surfaces first" decision, translation
coverage is real but intentionally partial:

- **Fully translated**: the public landing page (nav, hero, proof strip, footer), the
  Open Session public join flow (join form heading/labels/button), and the core sign-in
  screen (heading, hint, field labels, submit button).
  the invitation email (subject and body) is translated on the backend, activated by
  the request's `Accept-Language` header via Django's `LocaleMiddleware`.
- **Not yet translated**: the authenticated application (organisation workspace,
  decision reasoning, evaluations, disbursements, everything behind `/app`), most form
  validation messages, and most other transactional emails. These stay in English.

Extending coverage to a new page means: add a `defineCatalog` in
`frontend/src/lib/catalogs/`, call `useTranslations(catalog)` in the component, and
render `<LanguageSwitcher />` somewhere in that page's header. No structural change is
needed.

## Translation quality: AI-assisted, unreviewed

Every French and Portuguese string in this codebase — both the frontend catalogs and
the backend `.po` files — was produced with AI assistance and has **not** been reviewed
by a native or fluent speaker. This is stated explicitly, not hidden: treat the current
copy as a structurally-complete placeholder that unblocks the i18n plumbing, not as
final, publish-ready translation. Before using French or Portuguese copy in front of a
real funder, community, or applicant, have a native speaker review:

- `frontend/src/lib/catalogs/*.ts`
- `backend/locale/fr/LC_MESSAGES/django.po`
- `backend/locale/pt/LC_MESSAGES/django.po`

## Regenerating backend translations

```bash
docker compose exec backend python manage.py makemessages -l fr -l pt --no-obsolete
# edit backend/locale/{fr,pt}/LC_MESSAGES/django.po
docker compose exec backend python manage.py compilemessages
```

`makemessages`/`compilemessages` require the GNU gettext tools (`msguniq`, `msgfmt`).
They are not part of the base backend image; install them in the running container with
`apt-get install gettext` before regenerating, or add the package to the Dockerfile if
translation work becomes routine.
